# VaultDesk 阶段性工作记录 — 2026-08-27

主题：新用户 clone 体验验证中发现问题的定位与修复（个人化残留清理 + 界面改进）。

## 一、背景

本仓库从个人 Obsidian 网页工具精简而来。为验证「新用户 clone 后即可使用」，拉取到独立目录运行，发现三类问题：

1. 项目中出现只有作者本机才有的东西（如 `kb-search.py`）；
2. 界面问题：顶部菜单与左侧导航重复、LM Studio 地址用处不明、设置页混乱；
3. 运行行为对非作者环境不友好（控制台报错、错误提示不可理解）。

## 二、问题定位结论

### 1. `kb-search.py` 之谜（文件并不在仓库里）

排查确认：仓库中**不存在** `kb-search.py` 文件（`git ls-files` 与全目录查找均无）。它是作者个人 vault 内的自备脚本（个人目录约定 `00_META/scripts/kb-search.py`）。新用户之所以"到处看到它"，是因为旧代码把它写成了硬编码默认值：

- `server.js` 旧默认 `KB_SEARCH_SCRIPT = $VAULT/00_META/scripts/kb-search.py`，问答时每调用一次就刷一次 `python3: No such file` 报错；
- 设置页有一项指向该神秘路径的字段，提示语含糊（"留空时使用默认位置"）；
- README 把它写成运行要求的一部分。

**处理**：`KB_SEARCH_SCRIPT` 默认改为空 = 功能不启用；仅显式配置时才调用，且找不到时只提示一次。README 与设置页说明同步改写为"完全可选"。

### 2. 连带发现的真 Bug：向量索引跨 vault 泄漏

测试中实测发现：更换 `OBSIDIAN_VAULT_ROOT` 后，语义检索仍返回**旧 vault 的笔记**——`data/vector-meta.json` 没有记录构建时的 vault 根目录，旧索引在新 vault 下继续生效（`meta.root` 存的是 vault 内相对目录，空值无法校验）。这正是"作者个人数据混进新环境"的一类根源。

**处理**：索引元数据新增 `vaultRoot`（构建时的 vault 绝对路径）；`loadVectorMeta()` 发现 `vaultRoot` 与当前 vault 不符、或属于没有 `vaultRoot` 的旧格式索引时，一律作废并提示在设置中重建；增量索引任务在无有效元数据时自动退化为全量重建。

### 3. 界面问题定位

- **顶部菜单与左侧重复**：顶栏 6 个 tab（每日日记/待办/资讯/笔记/问答/设置）与侧栏 8 个导航项大面积重复，且命名不一致（"待办事项" vs "全部笔记"）。
- **LM Studio 地址用处不明**：设置页仅有 label「LM Studio 地址」+ hint「OpenAI 兼容接口地址」，未说明它服务于知识问答/语义索引，也未说明不装 LM Studio 是否影响使用。
- **设置页混乱**：9 个配置项平铺一列，vault 路径、保存路径、AI 服务、服务器端口混排，无分组无主次。
- **硬编码个人内容**（"只有作者才有"在界面上的体现）：
  - 问答模型下拉写死 `qwen3.5-2b (本地推荐)`（作者个人模型）；
  - 问答检索范围写死 `notes/Daily/resources`（作者 vault 目录）；

## 六、追加（2026-08-28）：关键词检索内置化

**决策**：此前 `KB_SEARCH_SCRIPT` 默认不启用，新用户零配置时问答完全没有关键词来源，还需要自己写 Python 脚本才能解锁——这是个人工具时代的包袱。现改为：

| 场景 | 行为 |
| --- | --- |
| 未配置 `KB_SEARCH_SCRIPT`（默认） | 使用**内置 Node 关键词检索**，零配置可用 |
| 配置了脚本且正常 | 脚本结果优先，替换内置实现（保留高级用户/ripgrep 等自定义能力） |
| 脚本路径不存在 / 执行失败 / 输出非法 JSON | 自动回退内置检索，仅警告一次（此前是关键词来源直接变空） |

**实现**（server.js）：`builtinKeywordSearch()` 扫描启动时已建好的内存笔记索引 + 文件正文（单文件截断 512KB），按 标题×8 + 路径/标签×4 + 正文命中数（上限 50）计分，支持多词与整句短语、大小写不敏感的子串匹配（兼容中文），返回与脚本相同的 JSON 契约（`path/line/title/score/scope='keyword'/tags`）；`runKbSearchScript()` 负责脚本调用与回退；`buildKeywordSources()` 统一构建摘录素材。

**验证**（临时测试 vault，四场景）：默认命中 `scope=keyword` 且正确排除无关笔记；自定义脚本结果被采用（scope=custom-script）；非法输出与路径不存在均回退内置且警告恰好一条。README（中英）、设置页 hint/分组说明已同步。

**已知限制**：内置检索每次问答全量扫描候选文件，超大 vault（万级文件）可能到秒级；后续可按 mtime 做内容缓存，或建议重度用户切回自定义脚本。

## 八、追加（2026-08-28）：设置页补齐 RSS 源配置

**背景**：此前 RSS 源只能看不能配——「资讯聚合」页只有一个"添加 URL"输入框，且 `/api/feeds/add` 把源写进**随仓库分发的 `feeds.json`**：新用户一添加源仓库就变脏，与"清除个人化痕迹"的改造目标背道而驰；同时没有查看/编辑/删除源的入口。

**方案**：源配置分两层，用户配置优先——

| 层 | 位置 | 生效条件 |
| --- | --- | --- |
| 用户自定义源 | `data/feeds.json`（gitignored） | 存在且非空时**整体替换**内置默认 |
| 内置默认源 | 仓库根 `feeds.json` | 无自定义源时兜底（其后再兜底 `defaultFeeds()`） |

**实现**：
- `server.js`：`loadFeedsConfig()` 改为分层读取；`saveFeedsConfig()` 改写 `data/feeds.json`（`/api/feeds/add` 因此自动不再弄脏仓库）；新增 `parseFeedsText()`/`feedsToText()` 做文本↔结构化转换（每行 `名称 | URL | 条数`，名称/条数可省略，缺省名取域名，key 由域名生成并去重，上限 50 源、单源条数 1-50）；`GET /api/settings` 返回 `rssFeeds: {custom, text}`，`POST /api/settings` 接收 `rssFeeds` 字段（先整体校验再落盘，避免半提交；清空 = 删除用户文件恢复默认），保存后后台触发一次增量抓取让新源尽快出内容。
- `public/app.js`：新增「📡 资讯聚合」标签页（置于「保存位置」之后，共 6 个标签），含 RSS 源列表多行编辑器（复用模板编辑器样式）与提示文案（显示当前是自定义源还是内置默认源）；`VAULT_RSS_READ_LATER_PATH` 从「保存位置」移入本标签；表单提交把 `rssFeeds` 一并交给 `saveSettings()`。
- `.gitignore`：补充 `data/feeds.json`。
- `README.md`（中英）：RSS 源章节改为两层配置说明，运行时文件清单、功能列表同步。

**验证**（重启服务后 curl + 浏览器）：保存自定义源（含省略名称的行）→ 200、`custom:true`、`/api/feeds` 只剩这两个源且自动命名；非法行 → 400 且报错指明行号；清空保存 → 用户文件删除、恢复 5 个内置源；`git status` 全程干净（内置 feeds.json 未被触碰）。浏览器确认「资讯聚合」标签页渲染、文本框预填当前生效源。

**遗留**：删除单个源目前靠在设置里编辑文本行；`/api/feeds` 对已删除源的旧缓存条目不清理（不展示，无实际影响），后续可在保存配置时顺手裁剪缓存。

## 九、追加（2026-08-28）：目录类配置支持弹窗选择

**需求**：设置中所有编辑目录的地方，允许直接填写，也可弹窗选择目录。

**技术前提**：浏览器安全模型拿不到本地绝对路径（`<input webkitdirectory>` 只给文件列表），所以"选目录"必须由服务端配合：新增目录浏览接口，前端做浏览式选择弹窗（这也是不做成系统原生对话框的原因——网页无此能力）。

**实现**：
- `server.js`：新增 `GET /api/browse-dir?path=`，返回 `{path, parent, home, dirs[]}`；只列子目录名（过滤 `.` 开头的隐藏目录，按中文本地化排序），不读任何文件内容；空路径默认用户主目录，路径不存在返回 400 中文报错。
- `public/index.html`：新增 `#dirPickerModal`（原生 `<dialog>`，复用 task-modal 面板样式），含路径条、子目录列表、上级/主目录/取消/选择此目录。
- `public/app.js`：`initDirPicker()`/`loadDirListing()`/`openDirPicker()` 三件套，弹窗内点目录逐级进入；`settingsFieldHtml` 支持 `picker: true` 渲染"选择…"按钮（Vault 根目录启用，回填绝对路径）；语义索引的「向量化的目录」同样加按钮，选中后自动转成 vault 内相对路径（选中 vault 根 = 留空 = 整个 vault，选到 vault 外则 toast 拒绝）。文件路径类配置（待办文件、日记路径、稍后读、问答保存）不属于目录，保持手填。
- `public/styles.css`：`.dir-picker-*` 弹窗样式 + `.settings-input-row`（输入框与按钮同行）。

**验证**（重启 + 浏览器实测）：接口三用例（列目录/空路径回主目录/不存在路径 400）通过；弹窗从当前值起步 → 主目录 → 进入 tools → 选择此目录，Vault 根目录回填 `/Users/username/tools`；向量化目录弹窗以 vault 为起点、选中 Daily 后回填相对路径 `Daily`；Esc/取消正常关闭；`npm run check` 通过。验证用的表单值未保存，页面刷新已还原。

**安全说明**：`/api/browse-dir` 会向能访问服务的人暴露目录名列表，因此保持默认 `127.0.0.1` 监听即可；若按 README 建议仅在可信局域网开放 `0.0.0.0`，请知悉此接口可见。

## 十、追加（2026-08-28）：模型选择支持自定义输入

**需求**：嵌入服务模型和 AI（对话）模型允许用户输入自定义配置，而不仅从检测列表中选择。

**方案**：两处模型选择器由 `<select>` 改为「`<input list>` + `<datalist>`」组合——下拉仍给检测到的建议，同时允许手输服务中实际存在但未列出的任意模型 id。服务端本就把模型 id 透传给后端服务（Ollama / LM Studio / DeepSeek），无需后端改动。

- `/api/restart` 派生子进程时改传 `env: { ...process.env, ...readEnvFileValues() }`——用 .env 最新内容覆盖后继承，网页重启立即应用新配置。

**背景**：用户问「今天我做了哪些事儿」后-spinner 长时间不动，反馈「速度慢，用 qdrant 代理向量模型如何」。先量化各阶段耗时再动手：查询嵌入（qwen3-embedding:0.6b）冷 2.3s / 暖 0.25s；语义检索为 JS 暴力扫描 52 万 chunk × 1024 维，实测 1.44s；LLM 生成（qwen3:4b）55s——**大头是对话模型，不是检索**；且用户自定义 自定义网关离线时对话请求会挂满 5 分钟超时。另发现若本地内存紧张时，node 常驻向量缓存可能加剧内存换页。

**实现**（server.js / app.js / .env）：
- **本地扫描优化**：`ensureVectorCache` 加载向量时预计算全部 chunk 范数（`buildVectorNorms`，一次性 ~0.7s），检索只算点积——52 万块全库扫描 1.44s → 0.84s；`saveVectorMeta` 同步失效 norms。
- **Qdrant 可选后端**（零新依赖，REST 直连）：`.env`/设置页新增 `QDRANT_URL`（现读配置，留空=不启用）。点位 id 采用 meta 内分配的稳定 `chunk.p`（`nextPid` 计数器），payload `{rel, o, root}`；索引任务边嵌入边双写（256 点/批，熔断保护：连续失败 2 次弃队列 60s，绝不禁锢索引任务）；后台对账同步 `qdrantSyncJob`（启动 10s 后 / 索引完成 / 设置保存后触发，按点位数对账：远端少=补推、远端多=重建集合）；`searchSemantic` 优先走 Qdrant ANN（顶层目录前缀转 `root` 过滤，深层前缀超量取回后本地过滤），失败回退本地扫描；`/api/vector/clear` 联动删集合；`/api/vector/status` 附带 `qdrant` 状态。**Qdrant 健康时检索路径不再加载 2GB 本地向量缓存**（node 常驻内存 ~50MB），换页问题随之消失。
- **网关快速失败**：`callLLM` 自定义服务分支前置 `assertGatewayReachable`（2.5s 探测 `/models`，仅网络层失败视为不可达，失败结果缓存 30s）——网关离线从挂 5 分钟变为 ~3s 内明确报错。
- **耗时透明化**：`/api/chat` 返回 `timings {searchMs, llmMs, totalMs}`；来源组件标题显示「检索 X 秒 · 生成 Y 秒」；问答页语义检索徽标显示 Qdrant ✓/✗。
- **Qdrant 部署**：为减少容器环境资源占用，改用官方 macOS arm64 原生二进制装至 `~/tools/qdrant`（v1.19.0，REST 6333/gRPC 6334，存储 `~/tools/qdrant/storage`，nohup 后台运行）。

**验证**：全量同步 520,634 点位约 12 分钟完成；对账空转正常（520,636=520,636，增量双写自动补齐）；Qdrant 检索 0.05-0.06s vs 本地扫描 1.44s（~25×），三路得分与本地扫描完全一致（0.704/0.669/0.663）；自定义网关离线 10s 内报错（原为 5 分钟挂起）；完整问答 `timings: search 6.8s（其中 LLM Wiki 检索占大头）/ 生成 55.2s`。`npm run check` 通过。

**后续建议**：问答等待大头在生成端——可选流式输出（首 token ~2s 即见）、或接回 自定义网关用更快模型；建议关注本地后台常驻进程与内存占用情况。
